# 高频使用下的 Agent 调度与阻塞治理

整理日期：2026-10-03

当前版本：0.2.3（2026-10-04 更新能力说明）

状态：待办整理，尚未实现以下新增能力。

## 目标

频繁派发任务时，把独立工作分配给合适的 worker，减少单个 Agent 的负担、排队和相互拖累，逐步形成类似负载均衡的效果。

Bridge 管理任务执行；宿主 Agent 负责拆分任务、选择执行资源和验收结果。分流是否提升吞吐，取决于任务能否独立执行，以及模型服务是否有可用容量。

## 当前能力与限制

- 已支持异步派发、状态查询、显式时间预算、取消、请求去重、已保存结果恢复，以及宿主明确发起的检查点或原生会话续接。
- 各 worker 已接入运行时进度，提供最近活动、工作阶段和工具进度；监督进程心跳不代表 worker 有进展，缺失遥测时仍标记未知。
- 同一项目只允许一个 Bridge worker 运行；冲突任务会被拒绝，没有自动排队。
- worker、provider、model、effort 由宿主明确选择；已提供质量优先的推理建议、结构化任务交接和逐项宿主验收，没有自动负载均衡、故障切换或自动续跑。
- 多个 worker 可能共用同一模型服务或账号，仍受共享额度和限流约束。
- 权限等待、用户输入和宿主会话自身卡住，不能仅靠增加 worker 解决。

## 待办

### P0：排队与阻塞可见性

- [ ] 增加持久化任务队列：项目忙时进入等待，释放锁后再启动；支持查询和取消排队任务。
- [ ] 区分排队、等待模型、工具执行、等待交互、进度未知和异常停止，说明当前等待原因。
- [ ] 设计调度触发与宿主通知机制，让宿主无需持续轮询也能知道完成、失败或需要处理的阻塞。
- [ ] 制定无进展处理策略：结合有效活动、监测是否可用和任务时间预算判断；不能仅凭耗时或没有文件修改判定卡住。

### P1：负载感知与任务分配

- [ ] 记录 worker 的运行任务数、近期耗时、失败和超时情况。
- [ ] 按实际模型服务及共享配额分组控制并发，避免把共用后端的 worker 当成独立容量。
- [ ] 提供调度建议或可配置规则，依据任务能力要求、可用容量和近期健康情况分配任务。
- [ ] 支持限流后的退避、冷却和有界重试；重试前确认旧进程已结束，并检查已有结果和部分修改。
- [ ] 定义明确授权的备用执行资源；切换时核对实际目的地、读取范围和模式，并保留选择记录。

### P1：隔离并发执行

- [ ] 设计独立 checkout / worktree 的执行方式，允许互不冲突的任务并行运行。
- [ ] 区分只读和修改任务的并发规则，同时限制全局并发数。
- [ ] 定义修改结果的验收、冲突处理和合并流程，防止多个 worker 同时修改同一工作目录。

### P2：效果评估

- [ ] 统计排队时间、执行时间、端到端耗时、完成率、超时率和需要人工处理的比例。
- [ ] 用相同任务集比较串行执行与调度后的结果，确认吞吐和质量是否改善。
- [ ] 区分 worker 数量增加与模型服务容量增加带来的效果，避免把任务分流直接等同于提速。

## 验收场景

1. 同一项目连续提交多个任务，能够排队、查看等待原因，并按规则执行或取消。
2. 一个 worker 卡住时，其他独立项目或隔离工作目录中的任务仍能推进。
3. 多个 worker 共用模型服务时，不突破配置的并发与限流预算。
4. 任务异常停止后，不重复执行已完成工作，也不在旧写入进程存活时启动新的修改任务。
5. 等待权限或用户输入时，能向宿主暴露原因并请求处理。

## 实施边界

- 本文件记录后续方向，不代表已确定实现方案或已授权派发任务。
- 保留用户指定的执行资源、目的地授权和宿主审批；不自动批准 worker 的交互请求。
- 取消不会回滚源码，恢复已保存结果不等于继续执行任务；执行续接必须重新预检并由宿主明确提交。
- 队列、重试和调度日志继续保护凭据及任务内容，不将运行产物提交到仓库。
